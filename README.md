# Лабораторная работа №2. Базы данных (МГТУ «СТАНКИН»)

Дополнительные задания: автоматизированный ГИС-анализ на Python и интерактивная карта.

Скрипт `task_gis_integration.py`:

1. Одним запросом получает из **Overpass API** (OpenStreetMap) полигоны парков Москвы.
2. Объединяет их в один MultiPolygon в оперативной памяти (`shapely.ops.unary_union`), чтобы избежать проблемы N+1 сетевых запросов.
3. Одним запросом забирает координаты единорогов (GeoJSON Point) из **MongoDB Atlas** (`learn.unicorns`).
4. Локально проверяет, какие единороги находятся в парках.
5. Строит интерактивную карту `moscow_parks_unicorns.html` (**Folium**) с инверсией осей: MongoDB хранит `[долгота, широта]`, а Folium ожидает `[широта, долгота]`.

## Запуск

```bash
pip install -r requirements.txt
```

Создайте файл `.env` в корне проекта:

```
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-url>/learn?retryWrites=true&w=majority
```

```bash
python task_gis_integration.py
```

После запуска откройте `moscow_parks_unicorns.html` в браузере.

## Отличия от эталонного скрипта из методички

- Строка подключения берется из `.env`, а не хранится в коде.
- Запасные серверы Overpass API: при ошибках 502/504 скрипт переключается на зеркало.
- Запрос парков ограничен прямоугольником старой Москвы, потому что запрос по всей области RU-MOW не укладывался в таймаут.
- Крупные парки (relation в OSM) собираются из кусков контура через `linemerge` и `polygonize`. В эталоне каждый кусок замыкался отдельно, и точки внутри крупных парков не находились.
- Подложка карты Esri: серверы OpenStreetMap блокируют (403) загрузку карты из локального HTML-файла.
- Таймаут выбора сервера MongoDB увеличен до 30 с, чтобы дождаться выборов нового PRIMARY в Atlas.
